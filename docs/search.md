# 原生国家显示名 Unicode 搜索

外交页的国家名单已接入标准 UTF-8 搜索。范围限定为国家显示名过滤；通用字符串查找的其他调用者仍保留原生字节偏移契约，国家内部标识符不做规范化。

## 匹配与原文

搜索使用 ICU NFKC casefold 键，处理规范等价、Unicode 大小写展开和全角等价。游戏原先的 CP1252 预处理还提供重音不敏感搜索，并把 Æ 映射为 A、ß 映射为 S。新模块对完整 Unicode 标量保留这些已存在的等价关系，同时接受 Unicode casefold 的 ß → ss；不会对 UTF-8 续字节应用单字节转换。

查询和候选名称原文保持 UTF-8，两个搜索键仅保存在内部缓存。缓存每线程限制 1024 条、1 MiB 文本载荷；缓存清空时，当前匹配所持有的键仍有效。

## 引擎入口

EU4 1.37.5 的国家过滤调用位于 RVA `efc38f`，返回地址为 `efc394`。它只检查是否找到候选，不使用匹配偏移。适配函数仅对该调用者返回找到/未找到结果；其他 `17061a0` 调用者继续调用原函数。

候选名的 `efc33b`、`efc344` 与查询的 `f16156`、`f1615e` 四处单字节预处理调用替换为 NOP，避免先破坏 UTF-8 再搜索。所有位置纳入启用前指令检查与回滚事务。

## 原生验收

专用夹具以法国为玩家，将外国国家名设为 `École Straße Ａ 英格兰𠀀` 与 `ΕΛΛΑΔΑ МОСКВА 卡斯蒂利亚`。名单会排除玩家国家，因此不使用玩家本国作为唯一匹配对象。

12 组查询通过：基本汉字、U+20000、U+10000 不误匹配 U+20000、重音、分解组合重音、ß 的 Unicode 展开与既有单 S 行为、全角、希腊文、西里尔文、无匹配负例和多轮查询恢复。每组实际检查 185 个原生候选；全角 a 的查询匹配 111 项，其余正例各匹配专用的一项。查询字段、原生过滤条件和候选原文均核对。

证据：[全部查询与原文](evidence/country-search.json)、[原始运行记录](evidence/country-search-trace.jsonl)、[原生名单画面](evidence/unicode-country-search.jpg)。DLL 指纹为 `f6c17af6944cad7178468ccde42b5ac9319564955c1425472cc4337c2b09c1cd`。

```powershell
.\tools\prepare-test.ps1 -SystemFonts -SearchProbe
.\tools\start-test.ps1
..\EU4MenuPatch\.venv\Scripts\python.exe tools\trace-search.py --duration 900
```

载入法国隔离战局、关闭夹具事件、打开外交页，点击 Name 排序开始。随后按脚本提示逐次点击 Name 排序，观察游戏自然刷新的名单。脚本通过原生编辑框 SetText 与已观察的回调设置查询，结束后保留最后结果 30 秒，再关闭专用进程。独立检查：

```powershell
..\EU4MenuPatch\.venv\Scripts\python.exe tools\verify-search-trace.py
```

跟踪点放在 `efc383` 的参数存储指令和 `efc394` 的返回后指令，保留原生 CALL 与被调函数。直接在 CALL 处或被调函数的返回处挂观察会替换返回地址，使调用者限定失效，产生假的大小写匹配失败。

此验收验证原生过滤与原文隔离。查询由程序设置，不据此声称物理键盘、剪贴板或中文输入法已通过。省份查找、国家选择页、其他搜索框和联机文本仍需逐一接入与验收。
