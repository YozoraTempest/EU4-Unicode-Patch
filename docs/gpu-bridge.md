# 原生 GPU 文本接口调查

目标为精确 SHA-256 的 EU4 1.37.5 x64。本次观察使用的 DLL 为 `550f804b53d5a599672d70e90df5823eec604309b630ae5ea9c0cea7759f98b3`。本次只在隔离实例读取原生绘制现场和 Direct3D 9 状态，没有上传纹理或替换绘制。

原生主文字 `15988e0` 内的缓存绘制路径返回地址为 `159b3b0`，调用 `16d4e90`。后者的 `RCX` 是包装对象，其首个指针指向渲染状态，状态 `+8` 是实际 `IDirect3DDevice9`；最终跳转到虚表 `+288` 的 `DrawPrimitive`。不能将主文字函数的第三、第四参数直接解释为屏幕 x/y；实测 HUD 标签在这些参数中出现 `2/0` 等模式值，实际变换仍需继续核对。

在四种 GUI 字号上，实际设备 getter 均返回成功。纹理宽高与原生字体 `+978/+97c` 一致：14 号为 1024×64，16/18 号为 1024×128，24 号为 1024×256。纹理为 `A8R8G8B8`、default pool；该设备报告单边上限 16,384。视口为 1280×720，原生字体绘制使用三角形列表，顶点 stride 为 28 字节。记录见 [现场状态](evidence/native-gpu-state.jsonl)。

进一步只在该缓存文字调用处读取实际顶点声明，得到以下布局；第一次未按调用者限定的读取得到地图顶点声明，已排除，不能作为 GUI 文字证据。

| 字节偏移 | Direct3D 声明 | 用途 |
| --- | --- | --- |
| 0 | FLOAT3 / POSITION0 | 三维位置 |
| 12 | FLOAT2 / TEXCOORD0 | 字体 UV |
| 20 | D3DCOLOR / COLOR0 | 打包颜色 |
| 24 | D3DCOLOR / TEXCOORD1 | 第二组打包数据，具体语义仍需确认 |

原始声明见 [限定调用者后的读取](evidence/native-gpu-declaration.jsonl)。虚表方法编号及结构布局根据本机 Windows SDK 10.0.26100 的 `shared/d3d9.h`、`d3d9caps.h` 核对；所有 `GetTexture`、`GetStreamSource` 和 `GetVertexDeclaration` 返回的额外 COM 引用均释放。实际 `FVF=0` 表明这条路径使用顶点声明，不能把 28 字节直接当成 `XYZRHW/UV` 固定管线结构。

设备使用 `SRCALPHA/INVSRCALPHA` 混合，深度测试与深度写入关闭；这些观察不能替代着色器和裁剪契约的调查。原生字体缓存可以复用已有顶点缓冲，因此按需/多页图集不能只在逐字符查找时切换纹理。需要让布局结果、图集世代、纹理页、批次刷新、缓存失效、设备 reset、颜色/图标和裁剪共享一致的状态。

下一步接入应先验证完整的坐标/着色器数据，再让保留实际字体的 shaped run 生成 GPU 批次，同时接入测宽与命中。现有稀疏码点表与位图路径继续承担已经验收的绘制。此调查没有完成 GPU 字体桥、运行时任意字符、多页字体、复杂文字或地图排版。
