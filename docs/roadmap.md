# 完整 Unicode 支持范围与验收

目标：先让标准 UTF-8 在 EU4 的真实文本路径中可用，再完成生僻字、多语言字体、复杂排版、输入编辑、搜索、持久化与联机。源码、标量与字形 ID 保持独立，字体后端的实现不能改变文本存储编码。

## 推进约束

先保留可以端到端运行的 UTF-8 位图路径。系统布局模块通过后，接入游戏的绘制桥，并让测宽、命中测试与文本绘制共享布局结果。生僻字不应通过截断到 16 位或改写文本编码来解决。

字体应按实际使用缓存字形，设置明确的内存和纹理预算；字体回退使用成熟系统 API。复杂文字必须使用 shaping 与 bidi 的结果，逐码点绘制不能替代正确排版。CPU 诊断图片只验证独立模块，不能作为游戏中生僻字显示的证据。

输入实验保持显式开关，直到中文提交、完整字素删除、选区和持久化往返得到游戏证据。联机验证依赖文本协议和实际双端环境，不能用离线单元测试宣称通过。

正式游戏目录、用户现有存档和旧汉化模组的变更，应在隔离验收和可检查的安装方案准备完成后进行。当前授权开发与测试使用独立副本。
