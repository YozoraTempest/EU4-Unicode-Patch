# 后续任务

目标是保持标准 UTF-8 文本存储，逐步完成扩展字形、统一排版、编辑、搜索、持久化与联机。已有结果见[测试记录](validation.md)，运行方法见[README](../README.md)。

## 推进顺序

| 阶段 | 已有基础 | 下一项验收 |
| --- | --- | --- |
| 按需字体稳定性 | 私有开源字体、固定页动态字形、实际 GPU 读回和独立设备 Reset | 其他字号/地图/控件新增字符；长期增长、缺字和满页；游戏设备恢复 |
| 图集容量 | 稳定字形指针、共享纹理和固定 UV | 明确全局预算、多页批次、缓存淘汰与失效、原位热重载 |
| 统一复杂排版 | DirectWrite 实际字体、shaped run、cluster、bidi 和独立栅格 | 游戏测宽、GPU 绘制、光标和选区共享同一布局；颜色/图标/裁剪回归 |
| 输入编辑 | 单行 UTF-8 提交、字素编辑、候选 UI 和基本中文物理复验 | 更多汉字/输入法/控件/缩放；预编辑、系统剪贴板、物理鼠标、多行与撤销 |
| 搜索与持久化 | 外交国家名过滤，中文/扩展路径，名称和月度自动保存往返 | 其他搜索入口；输入产生的名称、其他保存周期和云存档 |
| 联机与发行 | 精确版本/冲突保护、隔离实验包 | 双端文本协议、昵称/聊天/同步、铁人/模组/长期回归；正式目录安装与更新方案 |

## 验收原则

- 不改变源文本编码或截断到 16 位来扩大字形覆盖。
- 测宽、绘制、命中与选区必须使用一致的字形和 cluster 数据。
- 原生缓存会复用 UV，多页实现同时处理纹理页、批次、缓存世代和设备恢复。
- 字库 cmap、独立 CPU 图片、GPU 上传、实际游戏绘制和物理输入各有独立验收范围。
- 存档重读先移除生成名称的夹具，检查实际文件与正确原生字段。
- 联机需要真实双端环境；离线测试不能替代同步验收。

正式安装包依赖上述隔离验收和可检查的安装/移除方案；本次实验版继续保留隔离目录限制。CI 模板在源码中保留，远端运行尚未启用。
